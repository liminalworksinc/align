## A. Who may do what

Server truth: `lib/v2/changes.ts`, `lib/v2/approval.ts`. Route: `POST /api/v2/workspaces/{ws}/goals/{goal}/change-requests/{id}/{action}`, cookie only. Viewers get 403 `read_only` on every action (changes.ts:425).

## D. Launch and conditions (built on main; verify, don't rebuild)

### D1. Launch releases the plan to agents (RULED 33ad545d; launchers RULED 18efed56)

On main: approval stores `approved_json` only and writes no goal version or directive (changes.ts:17-18, 480-489). Launch calls `writeGoalVersion` in the action's transaction, which writes the `goal_version` directive (changes.ts:504-511; goals.ts:549-605, directive at 595).

- [ ] [API] **Acceptance test: approve without launching.** Take a goal at v<n> with a bound session and a connected MCP client. Approve and don't launch. Assert: no new `goal_version` directive (cursor unchanged); `align_get_goal`, `align_list_goals`, `align_get_limits` and `align_get_brief` return v<n>; the brief lists the request under "APPROVED, NOT LAUNCHED" (register.ts:1071). Then launch: one directive carrying v<n+1>, and the reads return v<n+1>. Repeat with "Not yet" then launch, and with Approve and launch.
- [ ] [API] **Decision record before launch.** `align_get_decision_record` returns an approved, unlaunched request with `diff.after` = the approved content, `resulting_version` null and `launch` pending or not_yet (changes-read.ts:109-130). Assert that `launch` is always present on that output, so no agent reads approved content as the current goal.
- [ ] [E2E] **Record wording** (launch-words.ts:10-15): before launch "Approved, agents still on v<n> until launch"; after launch "Launched, agents on v<n+1>"; superseded "Superseded before launch: it never reached agents." Never imply agents executed anything.

### D2. "Accept if…" = requester acknowledgment (RULED 35376283)

On main: `condition` on a counter revision (changes.ts:105-108, 572, 602); only the requester can acknowledge, storing `acknowledged_by`/`acknowledged_at` (changes.ts:546-557). It never gates approval or launch (ADR 0003 lines 57-58) and is never sent to agents (changes.ts:787).

- [ ] [API] **Acceptance test.** Accept if… with a condition. The requester accepts the counter (acknowledging while `countered` is 409 `wrong_state`). A non-requester acknowledges: 403 `not_requester`. The requester acknowledges: who and when are stored. A repeat: 409 `already_acknowledged`. No condition: 409 `no_condition`. Approve, then launch: the record shows condition, acknowledgment and approval together.
- [ ] [E2E] Before acknowledgment the condition reads "Not confirmed yet"; after, "Acknowledged by <name>, <time>". No "verified" wording or state anywhere.
- [ ] [API] `align_get_decision_record` and `align_list_change_requests` return the condition as `untrusted_text` with `acknowledged_by`/`acknowledged_at` (or null), declared in the zod `outputSchema`.

- [ ] [SCAN] UI state words match the MCP enums: change request `pending | countered | approved | rejected | withdrawn | superseded`; launch `pending | not_yet | launched | superseded`; goal `active | achieved | dropped`.

## E2. Evidence class on every agent-status surface (RULED 3770c6c4)

- [ ] [E2E] Each agent-status item shows exactly one evidence class: **delivery receipt** (a directive receipt, or a goal read Align saw), **agent reported** (the agent's own claim or evidence link), or **not observed**. "Agent reported" never looks like an observation.
- [ ] [API] MCP reads expose the same class on the same items.
- [ ] [E2E] With no receipts and no reports, Home shows "not observed", never working, stuck, blocked or diverged. A failed read shows "unknown", never zero.

## E3. v1 truth fixes missing on main (port before any tester sees v2)

- [ ] [API] **Seen means a read, not a connection.** `noteGrantUse` runs on every verified app request, including `initialize` and `tools/list` (app/api/mcp/route.ts:34-36). v1 fixed this in #56 (only `tools/call` counts). Any surface that shows "seen" or "last used" from `last_used_at` must either use `last_read_at` (goal reads) or get the #56 rule. Show the receipt from that data after launch, keyed to the launched version.
