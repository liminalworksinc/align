# Public interface: policy.authorize

## ADDED Requirements

### Requirement: policy.authorize

JavaScript module policy/authorize exports authorize(principal, action, object). PolicyPrincipal has userId and wsId strings, wsRole null or owner/member/viewer, and pods: a JavaScript ReadonlyMap from opaque team-id strings to lead/member. GoalObject has kind goal, ownerId string, visibility private/pod/workspace, and podId string or null. Identifiers are opaque, case-sensitive strings, including empty, Unicode and prototype-like strings. Do not validate or normalize identifiers. wsId supplies context but is not itself a condition in these functions. Preserve arguments and Map state; no I/O or hidden state. Return a Decision: allow is {ok:true}. Hidden is {ok:false,status:404,code:not_found,message:Not found}. Role denial is {ok:false,status:403,code:read_only,message:Viewers can look but not change anything.} for a viewer, or {ok:false,status:403,code:owner_only,message:Only a workspace owner can do this.} for other roles. Other denials below have ok:false and status:403. Return exact code and message strings, without additional properties. A principal with null wsRole cannot read any goal, even their own. Otherwise its owner can read it. Workspace goals are readable by all three workspace roles. Pod-visible goals are readable by a workspace owner or by a lead/member in the goal's nonempty podId. Private goals are readable only by their owner. A null or empty podId grants no team membership. These rules apply to all combinations of visibility and podId. Null workspace membership returns Hidden before checking any action or object. workspace.read, workspace.manage, session.share, session.stop_any, alignment.create and spend.read consult WORKSPACE_ROLE_ACTIONS from policy.data; object kind is irrelevant for these actions. An allowed role returns Allow, otherwise Role denial. goal.create first requires goal.create in the workspace role actions, otherwise Role denial. Then object must be {kind:goal_draft,podId:string|null}, otherwise Hidden. A nonempty podId requires the caller's team role lead or member, even for a workspace owner. Otherwise deny code not_in_team, message Only members of that team can add its goals. Null or empty podId requires no team membership. All remaining cases Allow. goal.read requires object kind goal and readability under policy.can-read-goal; otherwise Hidden. A readable goal returns Allow. goal.edit requires object kind goal and readability, otherwise Hidden. Then require goal.create in workspace role actions, otherwise Role denial. Only an ownerId exactly equal to principal.userId returns Allow; otherwise deny code not_goal_owner, message Only the goal's owner can change it. goal.bind requires {kind:bind,goal:GoalObject,hasTransfer:boolean} and a readable goal, otherwise Hidden. Then require session.share in workspace role actions, otherwise Role denial. Allow an exact goal owner, a lead/member of the goal's nonempty podId, or hasTransfer true. This team check applies regardless of visibility. Otherwise deny code alignment_required, message Ask the goal's owner to approve working toward it first. pod.manage_members requires {kind:pod,podId:string}, otherwise Hidden. A viewer always receives Role denial, even when they lead that team. A workspace owner or a lead of the nonempty podId receives Allow. Otherwise deny code not_team_lead, message Only a workspace owner or the team's lead can change its members. session.manage requires {kind:session,ownerId:string}, otherwise Hidden. Any workspace role may manage a session with ownerId exactly equal to principal.userId; all others receive Hidden. A workspace owner has no exception here. session.stop requires {kind:session,ownerId:string}, otherwise Hidden. Allow its exact owner, including a viewer, or a role with session.stop_any in workspace role actions. Otherwise Hidden. alignment.read requires {kind:alignment,involved:readonly string[]}, otherwise Hidden. Allow a principal whose exact userId is in involved, otherwise Hidden. Array order and duplicates do not change this decision. For each action preserve the order of checks above, including the different precedence of visibility, object-kind and viewer refusals. PolicyObject is the union of all object kinds described here; actions can be supplied any member of that union. The supported Action union is exactly the fourteen action strings listed above.
