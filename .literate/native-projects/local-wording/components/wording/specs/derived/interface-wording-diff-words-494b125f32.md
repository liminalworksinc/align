# Public interface: wording.diff-words

## ADDED Requirements

### Requirement: wording.diff-words

JavaScript module wording/diff_words exports diff_words(diff:Record<string,FieldDiff|undefined>,o?:ChangeWordsOptions):string[]. Process only title, measures, limits, status, depends_on, in that fixed order. For each field whose diff[field] is truthy, call change_words(field,diff[field],o) and append its lines in order into one new array. Ignore unknown fields. Pass the same options object and preserve callback order across fields. d has before, after, and optional hidden:{before:number,after:number}|null. o defaults to {} only when omitted or undefined. Use o.q unless nullish, otherwise identity; o.title unless nullish, otherwise identity; o.arrow unless nullish, otherwise the literal right arrow U+2192. Treat before and after as lists only when Array.isArray is true, otherwise as empty lists. For field 'measures', elements have id,text,target. Iterate after in order; find the first before element with the same id using strict equality. For a new element emit 'Added measure '+q(text), followed by ' (target '+q(target)+')' only when target is truthy. For a matched element whose text and nullish-normalized target both changed, emit 'Measure '+q(old.text)+' became '+q(new.text)+', target '+t(old.target)+' '+arrow+' '+t(new.target). t(x) is 'none' for null, undefined or empty string, otherwise q(x). If only text changed emit 'Measure '+q(old.text)+' became '+q(new.text). If only nullish-normalized target changed emit q(new.text)+' target '+t(old.target)+' '+arrow+' '+t(new.target). Then iterate before in order and emit 'Removed measure '+q(text) for every element with no matching id anywhere in after. When no lines were emitted return ['Measures reordered']. For field 'limits', elements have id,type,text. w(l) is (labels[l.type] ?? l.type)+': '+q(l.text), where labels is the ordinary JavaScript object {must:'Must',must_not:'Must not',out_of_scope:'Out of scope'} and property lookup retains its normal Object prototype behavior for names such as '__proto__' and 'constructor'. Iterate after in order, using the first before element with strictly equal id. A new element emits 'Added limit '+w(new); a matched element whose text or type changed emits 'Limit '+w(old)+' became '+w(new). Then each before element whose id occurs nowhere in after emits 'Removed limit '+w(old), in before order. With no lines return ['Limits reordered']. For field 'depends_on', lists contain ids. Added ids are after elements absent from before using includes; removed ids are before elements absent from after, retaining order and duplicates. more=max(0,(d.hidden?.after ?? 0)-(d.hidden?.before ?? 0)); fewer=max(0,(d.hidden?.before ?? 0)-(d.hidden?.after ?? 0)). When added is nonempty or more is truthy, emit 'Now depends on '+with_hidden(added.map(id=>q(title(id))),more). When removed is nonempty or fewer is truthy, then emit 'No longer depends on '+with_hidden(removed.map(id=>q(title(id))),fewer). With no emitted lines return ['Dependencies you can't see changed']. For field 'title', return exactly one line 'Title '+q(String(d.before ?? ''))+' '+arrow+' '+q(String(d.after ?? '')). For 'status', return exactly one line 'Status '+String(d.before ?? U+2014)+' '+arrow+' '+String(d.after ?? U+2014). For every other field, return one line field+': '+String(d.before ?? U+2014)+' '+arrow+' '+String(d.after ?? U+2014). U+2014 denotes the single em dash character as data. Do not quote status or unknown fields. Return a new array of exact raw strings.  These are synchronous dependency-free JavaScript functions with no I/O, clock or environment access. Preserve caller arguments, their properties and nested object identities. Use ordinary JavaScript values and callbacks, with no JSON transport wrapper. Do not sanitize text beyond each function's explicit cleaning rule. Number inputs retain JavaScript NaN, infinities, negative zero, fractional values and strict equality behavior. Formatting and quoting callbacks run synchronously in the specified order; preserve their return values' normal string coercion, call counts and arguments. Propagate the original callback error object without cloning or replacing it. Never suppress callback errors or invoke a callback on unused data.  Target comparison and rendering have different rules: compare (old.target ?? null) !== (new.target ?? null), merging only null and undefined. An empty string remains distinct from null even though t renders both as 'none'. Do not compare rendered target text or use truthiness to compare targets. With unchanged measure text 'A', a null old target and an empty-string new target produce ['A target none → none'] with default options. A custom q is called once for 'A' in that example and never for either missing target.
