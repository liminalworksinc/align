# Public interface: shell-words.parse

## ADDED Requirements

### Requirement: shell-words.parse

JavaScript module shell_words/parse exports parse(src). These are synchronous pure JavaScript functions over local strings and arrays. Perform no I/O, environment access, clock access, command execution or hidden state changes. Preserve all inputs and array properties. Names and string fragments are opaque, case-sensitive JavaScript strings, including empty, Unicode, prototype-like and malformed shell text. This is a heuristic reader for hook hints. Preserve the specified heuristic behavior rather than expanding it into a shell interpreter or a more permissive wrapper parser. Return an ordered array of ShellCmd objects. Every object has exactly words:string[] and redirs:{op:string,target:string|null}[]. Empty input returns []. Never throw for a string input. On an unexpected reader failure return only the output already accumulated. Do not expand variables, execute substitutions, resolve paths or interpret shell builtins. Read character by character, assembling a current word, an optional pending redirection target and a current command. Adjacent quoted, escaped and ordinary pieces concatenate into one word. An empty quoted piece creates an empty word. Only ASCII space and tab end a word; newline ends the command. Carriage return and other ordinary Unicode characters are literal word data outside the heredoc delimiter reader. When a word ends, if a normal redirection is pending, append {op:pending,target:word} to redirs; otherwise append it to words. Clear the pending redirection after committing a word. At a command boundary commit the word and, if a redirection still has no target, append {op:pending,target:null}. Emit a command only if it has at least one word or redirection. After emitting the containing command, emit any commands found inside its command substitutions, in their encounter order. Reset the current words and redirections at each command boundary. Outside quotes, # starts a comment only when there is no current word, including while a redirection is pending. Skip through the character before newline, then process that newline normally. A # inside an existing word is literal. A backslash outside quotes consumes and appends the following character verbatim; backslash plus newline contributes neither character. A trailing backslash contributes an empty piece. A single quote consumes up to the next single quote and appends the intervening characters verbatim, without quotes. An unmatched single quote contributes the entire remaining input. A double quote similarly appends a quoted word piece, but inside it backslash removes itself only before dollar, backtick, double quote, backslash or newline; an escaped newline contributes nothing. Before other characters the backslash remains literal. Inside double quotes process dollar and backtick spans using the rules below; otherwise all characters, including whitespace and redirection symbols, are literal. An unmatched double quote contributes its accumulated text without an error. A backtick span, quoted or unquoted, contributes the literal marker `...` including the backtick characters. Consume until the next unescaped backtick, skipping escaped characters; unmatched spans consume the rest. Commands inside backticks are never added to the output. A dollar followed by double opening parentheses contributes the literal marker $((...)); a dollar followed by an opening brace contributes ${...}. For these opaque spans consume balanced parentheses or braces respectively, count nesting, skip escaped characters and skip single-quoted spans; double quotes have no special meaning in this balanced-span reader. If no close exists consume the remainder. Opaque spans never produce inner commands. A dollar followed by one opening parenthesis, unless it starts the arithmetic form above, contributes the marker $(...). Recursively read commands until its matching closing parenthesis or the end of input. Collect those commands for emission after their containing command. Nested substitutions retain containing-before-inner order. A dollar not starting one of these forms contributes only the dollar character, leaving subsequent characters to ordinary reading. Apply these rules inside double quotes too. Outside quotes an opening parenthesis ends the current command and increases grouping depth. A closing parenthesis ends the current command. In a command substitution a closing parenthesis at grouping depth zero ends that recursive read and is consumed. Otherwise decrease grouping depth, bounded at zero, and continue. Outside substitutions an unmatched close still acts as a command boundary. Outside quotes semicolon, vertical bar and ampersand end a command, except ampersand followed by > starts a redirection. Consume the two-character separators ;;, &&, || and |& together; otherwise consume one separator. Empty commands between separators are omitted. Recognize redirections longest first: &>>, &>, >>, >|, >&, >, <<<, <<-, <<, <>, <&, <. If the current word consists only of decimal digits and the immediately preceding source character is a digit, discard that word as a file descriptor before handling the operator. Otherwise commit the current word. Normal operators become the pending redirection and their next word supplies the target. A new operator can replace a prior pending operator whose target has not begun. File descriptor numbers are not included in the returned shape. Quoted digits whose last source character is a quote are ordinary words. Preserve target text after the ordinary quote/escape/expansion rules, and preserve the operator spelling except <<- normalization. For << and <<-, immediately read a heredoc delimiter: skip spaces/tabs, then assemble pieces until whitespace or one of ; & | < > ( ) outside quotes. Strip surrounding single/double quotes from delimiter pieces; their contents are literal until the matching quote, or the rest if unmatched. Backslash includes only its following character. A nonempty delimiter queues a heredoc, with tab stripping enabled only for <<-. Always append {op:<<,target:null} immediately, never the delimiter text. Both forms normalize their returned op to <<. <<< is a normal redirection, not a heredoc. At newline, end the current command first, then consume queued heredoc bodies in FIFO order. Compare whole lines without their newline to each exact delimiter. For <<- strip leading tab characters only for this comparison. Skip the delimiter line too; do not parse any body line as commands, redirections or expansions. If a body has no closing delimiter consume the remainder. Multiple heredocs queued across the current line, including across semicolons, all consume bodies at that newline. After the bodies, continue normal reading. At the end of input, end the current command. A heredoc is an exception to pending normal-redirection replacement: appending a << or <<- redirection never clears or replaces an earlier pending normal redirection. That earlier operator stays pending until the next ordinary word supplies its target, a later normal redirection replaces it, or a command boundary records it with a null target. This applies even with an empty heredoc delimiter. Preserve this heuristic behavior for malformed input. For example, > <<; returns one command with words [] and redirs [{op:<<,target:null},{op:>,target:null}], in that order. echo > <<E followed by newline, body, newline, E, newline has words [echo] and the same two redirections. Adding the ordinary word target after <<E and before the newline makes the second redirection {op:>,target:target}; it does not add target to words. The rule applies to every normal operator, including <<<, with both << and <<-.
