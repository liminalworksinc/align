# Getting started

[Project guide](../README.md) > getting started

This dependency-free CommonJS library exposes create_creation, create_access
and create_disposable through server_workspace_admission's named modules.
Node 24 or later is required on macOS and Linux. Two clean qualifications ran
on macOS; the separate admitted package passes the same public and binding
acceptance on both hosts.

## Installation and usage

Register this ready child through the consuming project's supported native
library plan/apply command. Materialize its declared package from the admitted
portable cache. Supply the exact sixteen, eighteen and one resources in the
Node target `flavors/node-workspace-admission/flavor.md`.

Keep the original SQL handle and caller-owned transaction, errors, parsers,
array identities and operation-time readers. The package's pinned JSON asset
must remain exact beside its modules. There is no standalone service installer
or separately published npm package. See [parent integration](../roadmap/active-work.md#parent-integration).

## Contributor workflow

Use the pinned runtime and configured provider:

```console
litai project validate
litai lock components/server-workspace-admission --target workspace-admission-host-v1 --check
litai plan components/server-workspace-admission --target workspace-admission-host-v1
litai verify
```

After execution authorization, refresh the build and current receipt:

```console
litai rebuild components/server-workspace-admission --target workspace-admission-host-v1 --allow-host-execution --update-receipt
litai project test-receipt require-current --project .
```

A cache hit still requires current independent acceptance. Publish the admitted
entry to the declared local cache with the supported command:

```console
litai cache publish --project . --target project-committed
```

Preserve generated code, asset bytes, qualification and cache records. Change
intent through the Component and target, then regenerate. Read
[admitted acceptance](../evidence/admitted-acceptance.json), the
[framework flow](framework-flow.md), and [project map](project-layout.md).
