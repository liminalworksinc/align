# Public interface: trust-markdown.parse-inline

## ADDED Requirements

### Requirement: trust-markdown.parse-inline

JavaScript module trust_markdown/parse_inline exports parse_inline(text:string,opts:ParseOptions):Inline[]. Scan left to right with a text buffer. Flushing applies the fillText rule even to an empty buffer, then clears it. A backslash escapes the next character only when it is backslash, backtick, asterisk, underscore, either square bracket, either parenthesis, hash, vertical bar, either angle bracket, exclamation or hyphen; append that next character to the buffer and skip both. Other backslashes stay. A backtick uses the first subsequent backtick as its end. Flush, emit {t:'code',v:the exact interior}, and continue after it; the interior may be empty. An unmatched backtick stays ordinary text. Two asterisks use the first later pair searched after the opening pair; recognize strong only for a nonempty interior. Flush and emit {t:'strong',c:parse_inline(interior,opts)}. Otherwise continue with ordinary scanning. A single asterisk starts em only if its following character exists and is neither ASCII space nor asterisk. Use the first subsequent asterisk; the interior must be nonempty and its final character must not be ASCII space. Flush and emit {t:'em',c:parse_inline(interior,opts)}. Searches do not skip escaped delimiters or implement a different Markdown nesting algorithm. At an opening square bracket, find the first subsequent closing-bracket/opening- parenthesis pair, then the first closing parenthesis after that pair. Recognize a link only when both exist and its label contains neither square bracket. Empty labels and empty targets are permitted. Flush and recursively parse the label; pass the exact interior target to safe_href. With a truthy safe href emit a link node; otherwise append the parsed label nodes directly, discarding only the target. Parentheses inside a target do not balance: the first closing one ends it. At a less-than character, match /^<(https?:\/\/[^\s<>]+)>/i against the remaining input. On a match flush and call safe_href on the captured URL. A truthy result gives a link whose one text child is the captured URL. Otherwise emit a text node containing the captured URL without its angle brackets. Continue after the match. Every other character appends to the buffer; flush at end. Raw HTML delimiters remain ordinary text characters and underscores add no emphasis. Only parse_markdown removes comments; parse_inline treats comment delimiters as ordinary characters and still recognizes supported inline syntax inside them. When ordinary text is flushed, fillText uses opts.fill ?? {} and Object.keys in native JavaScript property order, keeping only own keys included in the original text. Inherited keys are ignored. With no matching keys, return one text node for nonempty text and no nodes for empty text. Otherwise quote each key as a literal regular-expression alternative, in that key order, and use a new global RegExp with flag g and without u. Iterate the original text's native String.matchAll; replacement values are never scanned again. Before each match emit one text node for any nonempty gap; then emit the fill value as one node. A value matching /^[^\s@<>()[\]]+@[^\s@<>()[\]]+\.[A-Za-z]{2,}$/ becomes {t:'link',href:'mailto:'+value,c:[{t:'text',v:value}]}; every other value becomes {t:'text',v:value}. Append a nonempty remaining suffix as a text node. Preserve alternative precedence and native numeric-key ordering, rather than sorting by key length. Empty keys are valid: native global matchAll advances through UTF-16 positions for zero-length matches, so even an empty flush can emit a replacement. Preserve regex metacharacters in keys literally. Repeated flushes remain separate; never combine adjacent text nodes. These are synchronous dependency-free JavaScript functions with no files, network, clock, environment access or hidden mutable state. Use ordinary values without a transport envelope. Preserve every argument, nested object, array, enumerable property, prototype and input reference. Strings are opaque UTF-16 strings; preserve exact text, order and node boundaries, including adjacent text nodes. When nodes or arrays are constructed, each call returns a fresh ordinary graph, including empty arrays; do not reuse result objects across calls. Never freeze caller objects. Formatting/resolution callbacks run only where specified, in order and with exact arguments. Propagate the original thrown callback value unchanged. Do not sanitize, normalize or interpret extra syntax beyond this grammar. Inline is {t:'text',v:string}, {t:'code',v:string}, {t:'strong',c:Inline[]}, {t:'em',c:Inline[]}, or {t:'link',href:string,c:Inline[]}. ListItem is {c:Inline[],sub:List|null}. A List is {t:'list',ordered:boolean,items:ListItem[]}. Block is a List, {t:'heading',level:number,id:string,c:Inline[]}, {t:'para',c:Inline[]}, {t:'table',head:Inline[][],rows:Inline[][][]}, {t:'code',v:string}, {t:'quote',c:Block[]}, or {t:'rule'}. DocPlace is {page:string,prefix:string}. ParseOptions has an opaque prefix:string, optional or nullish resolve:(path:string)=>DocPlace|null, and optional or nullish fill:Record<string,string>. The functions never alter fill or callback records.
