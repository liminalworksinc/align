# ADR 0005. Goal-list review and unbound usage

- Status **Proposed, pending founder approval**
- Scope LIM-2525, design section 5.8, phase 4 and decision 6

Show one workspace-wide share of metered usage without a goal. The draft calls for a minimum group size and leaves
the number open. This packet proposes five distinct people with positive fresh token usage without a goal in the
previous completed UTC calendar month. Missing or smaller groups show unknown. The percentage compares that
usage with workspace-visible goal usage plus unbound usage. Team and private goal usage cannot affect it.
The owner sees no contributor count, names, sessions, local usage or team cuts.

Count only accounts that the contributing records can still identify. A former member's pseudonym cannot
establish a distinct person because the same person may have returned. Keeping a link from the pseudonym to
an account would undermine pseudonymisation. Counting each pseudonym as a separate person could release a
figure for fewer than five people.

For a given workspace and month, show the first eligible aggregate. If either usage total changes or the
records no longer establish five contributors, show unknown for the rest of the period. Deletions still
remove the underlying history. Showing a new figure while five people remain can disclose one person's
usage through the difference. Waiting for changes from several demonstrably distinct people is another
option, but would require retaining contributor-level history to compare releases. Keeping the first
figure visible after deletion would still reflect deleted usage.

Leave target-gap questions to Allocation, which defines the actual share using all shared agent time.
A narrower denominator can flag a goal that met its target. Using the full denominator in this review could
reveal hidden goal usage or unbound usage below the proposed minimum.

Alternatives considered were three contributors, a higher minimum, and keeping all unbound figures on the machine.
Three would disclose the aggregate for a smaller group. A higher minimum would give fewer owners a usable share.
Keeping it local would preserve privacy at any size and leave owners without a workspace answer. Configurable
periods or a split by team could let readers compare overlapping groups, so this proposal uses one workspace scope
and fixed, non-overlapping months.

The existing metadata-only default remains in force. This review uses what shared sessions already reported and
introduces no permission for text or vendor requests. The draft's other decisions belong to the
packets that implement those capabilities.
